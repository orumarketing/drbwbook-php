# Change History

Plain-language records of meaningful updates to this site: schema changes,
new features, content-structure decisions. One markdown file per update.

This exists alongside (not instead of) git history. Commit messages say what
changed at the code level; these files explain the decision so a future
editor understands *why* the system is shaped the way it is before changing it.

## Conventions

- **File naming:** `YYYY-MM-DD-short-kebab-title.md`, dated to when the
  change landed.
- **Structure:** a `## What changed` section (bullets, concrete), then a
  `## Why` section.
- **The Why section is 200 words or less.** If it needs more, the change
  probably needs its own design doc — link to it instead.
- Reference files by repo path (e.g. `assets/json/more-titles.json`) so
  entries stay greppable.
